# The 0.27-content c8r promotion (2026-08-11)

The serving image moved from `v026-gx10-cand7-backports` (thin layer on official
vLLM **0.26.0**) to **`v0261-main-c8r`** (full-source build of upstream vLLM
**main @48bada6ea4** — 334 commits past the v0.27.0 release cut — plus the gx10
overlay and a measured-neutral #49731 revert). This page is the production receipt:
what was built, what the gate measured, the cold-cache lesson, and how to roll
back. Numbers are observations on one 2× DGX Spark pair; re-run the gates on your
hardware.

## Why leave the official 0.26.0 image

cand7 ([docs/13](13-vllm-026-cand7.md)) is a **source-patch** lane: official
`vllm/vllm-openai:v0.26.0` (linux/arm64) + a Python overlay. That model works only
while the delta stays thin. By 2026-08-11, main had **334 commits past the v0.27.0
release cut**, including packing and sparse-MLA work that is not deliverable as a
thin Python layer (and re-pinning to the v0.27.1 *tag* was rejected as a content
downgrade — its branch-only commits are CI/docs/other-models plus a FlashInfer bump
main already had).

The c8r lane is therefore a **full-source** build:

| Piece | Pin |
|---|---|
| Upstream tree | `main` @ `48bada6ea49ad7f3ecbe03128aa76562089c8b00` |
| Stage-1 | upstream `docker/Dockerfile --target vllm-openai`, `torch_cuda_arch_list=12.1a` → `vllm-dspark-src:v0261-main-c8` |
| Runtime layer | overlay0261 (14 files) + #49731 revert (3 files) → `vllm-dspark-runtime:v0261-main-c8r` |
| FlashInfer | native on main: **0.6.16.post3** (+cubin) |
| DeepGEMM | runtime layer rebuilds the 0.26.0-class pin (`deepseek-ai/DeepGEMM@a6b593d2`) — main's fork dropped the SM120 backend |
| Kit | [patches/vllm-0261-main-c8r/](../patches/vllm-0261-main-c8r/) |

There is **no registry base to pull** for this lane. Stage-1 is multi-hour nvcc on
the head node with the **cluster stopped** (nvcc does not fit next to the serving
pool on 121 GiB UMA). Prepare the pinned checkout once:

```bash
git clone https://github.com/vllm-project/vllm.git ~/vllm   # one-time, control host
git -C ~/vllm worktree add ~/vllm-0261-main-wt 48bada6ea4
bash bringup/05-build-image.sh --distribute   # or without --distribute + 06
```

## What the base buys (measured)

Same serve knobs as cand7 (`MTP_NUM_TOKENS=2`, `--no-async-scheduling`,
`KV_CACHE_MEMORY_BYTES=21316272128`, explicit `FLASHINFER_MLA_SPARSE_DSV4`,
0731 weights + revision pin). The gate was **throughput-parity** with a **larger
KV pool**:

| Metric | cand7 (same-day ref) | c8r (warm) | Read |
|---|---|---|---|
| C1 tok/s (mean of 6) | 34.24 | **33.85** (−1.14%) | Welch95 [−4.21, +1.93] **TIE** |
| C8 tok/s (mean of 6) | 87.68 | **87.78** (+0.11%) | Welch95 [−3.15, +3.38] **TIE** |
| Bench acceptance | 0.502 / 0.488 | 0.495 / 0.490 | flat |
| Eval acceptance | — | 0.800 (mean draft len 1.60) | in band |
| KV pool (same byte pin) | 2,948,751 | **3,027,217** (+2.7%) | #48993 MXFP4 indexer packing |
| Needles @ ~944K | 3/3 HIT | 3/3 HIT (c8 arm — same base, no-revert; inherited, not re-run on c8r) | unchanged |

The +2.7% pool is free capacity at 1M context (~2.89× concurrent full-length
sessions vs ~2.81×). No measured throughput tax on the warm gate.

## The #49731 story (why "c8r", not plain "c8")

A first full-source arm without the revert (`v0261-main-c8`) gated **C8 −3.91%**
on cold-ish roots. That looked like upstream #49731 (replicate the DSpark Markov
draft head across TP ranks) — the same class of suspect that cost cand6 −10.7% C8.
The contingency arm **c8r** reverts #49731 back to the standard TP-sharded draft
head (no per-rank replica). On a **warm** re-gate:

- c8r vs cand7: C1/C8 **TIE** (table above)
- c8r vs c8 (same base, with/without revert): **+0.62% C8 TIE**

So #49731 is **exonerated** as a C8 regression on this stack — the morning miss was
**fresh-root cold-compile noise**. The revert still ships: sharded is the standard
memory path, matches every other weight, and is measured perf-neutral. Keep it.

## Cold-cache lesson (do not re-learn this)

A full-source build has a **different version string** from any 0.26 source-patch
image. The compile cache keys on version+config → c8r **must** use its own roots:

```
VLLM_CACHE_ROOT=/cache/huggingface/vllm-cache-c8r
TRITON_CACHE_DIR=/cache/huggingface/triton-cache-c8r
TILELANG_CACHE_DIR=/cache/huggingface/tilelang-c8r
```

First boot on empty roots is a full cold compile (~12 min). The **first bench
reps run slow** — warm with `runtime/warmup.sh` / `eval-cluster.sh` / one long
generation **before** any promotion gate, or you will measure a phantom
regression (exactly what the morning c8 arm did on C8).

When rolling back to cand7, move **all three** roots back to the `-cand7` set (and
the image tag). Mixing image + roots is the stale-graph class of bugs.

## Serving knobs (unchanged from cand7)

- `MTP_NUM_TOKENS=2` (probabilistic DSpark draft) — n=3 is a fine fallback
- `--no-async-scheduling` (only off spelling on 0.26+; omit ≠ disable)
- `--attention-config '{"backend":"FLASHINFER_MLA_SPARSE_DSV4"}'` (explicit drift-guard)
- `DSPARK_REASONING=on` / `DSPARK_REASONING_EFFORT=high` — CoT in `message.reasoning`
- Loopback API `127.0.0.1:8000`, TP=2 over QSFP, worker-before-head

## 0731 trait still applies

Numeric length constraints and very long single-shot asks can burn the thinking
budget until `finish=length` with empty `content` (coherent re-draft, not garble).
Steer or chunk long-form; tool-use traffic is unaffected. See [docs/12](12-dsv4-flash-0731-upgrade.md).

## Rollback

1. **First rung:** image `vllm-dspark-runtime:v026-gx10-cand7-backports` + the
   `-cand7` cache roots (build with `bringup/05-build-image.prior-0.26-cand7.sh` if
   the tag is not already resident).
2. **Second:** `v026-gx10-cand4-backports` + pre-cand7 roots.
3. **Third:** `vgx10-011-pr47356` (0.25.1).
4. **Weights:** flip `DSPARK_MODEL` / `DSPARK_REVISION` back to
   `DeepSeek-V4-Flash-DSpark` (preview stays supported if both stay resident).

Documented in `runtime/cluster.env.example` and the patch README.
